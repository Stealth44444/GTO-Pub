# 플랫 뒤 스퀴즈 올인 설계

작성 2026-09-28. 크기 있는 3벳 설계(`2026-09-27-sized-threebet-design.md`)의 후속이다.

## 왜 하는가

엔진은 오픈에 첫 콜러가 나오면 뒤 자리를 모두 접는다. 그래서 뒷자리 플랫이 블라인드와
앤티(2.5bb)를 공짜로 가져간다. 콜러를 모두 BB(OOP) 표로 매기던 방식은 포지션 가치를
빼서 이 공짜 돈을 우연히 상쇄하고 있었다. 콜러별 표를 넣자 30bb에서 CO가 UTG 오픈에
42.5%, BTN이 CO 오픈에 49%를 플랫하고 플랍 도달률이 78%가 됐다(2026-09-27, 커밋
`6504367`). 스퀴즈 위험을 넣어야 두 오류 없이 풀린다.

## 범위

- 플랫 뒤의 자리들이 차례로 **폴드 / 스퀴즈 올인**. 크기 있는 스퀴즈, 오버콜(멀티웨이)은
  범위 밖.
- 스퀴즈에는 오프너가 먼저, 오프너가 접으면 플랫한 자리가 답한다. 콜은 한 명까지(오프너가
  콜하면 플랫한 자리는 접는다).
- 크기 있는 3벳이 나오면 뒤 자리는 지금처럼 접는다.
- 30bb 먼저. 20bb를 새 솔버로 다시 풀지는 결과를 보고 정한다.

## 엔진 (`src/lib/seatGame.ts`)

- `Stage`에
  - `{ kind: "vsFlat"; opener; caller }` — 폴드 | 올인
  - `{ kind: "vsSqueeze"; opener; caller; squeezer; iOpened }` — 폴드 | 콜
- `SeatsData` 자리 항목(오프너의 스팟 안), 키는 `[플랫한 자리][스퀴즈한 자리]`:
  - `vsFlatJam` + `ev.vsFlatJam` — 스퀴즈 빈도·EV
  - `vsSqueezeOpenerCall` + EV — 오프너의 콜
  - `vsSqueezeCallerCall` + EV — 플랫한 자리의 콜(오프너가 접은 뒤)
- `canSqueeze(data) = Boolean(data.seats[*].vsFlatJam)` — 없는 데이터(지금 20bb)는 지금과 같다.
- 흐름: 첫 콜(3벳 아님, 올인 대응 아님) → 플랫한 자리 뒤를 차례로 `vsFlat`로 묻는다 →
  스퀴즈면 `answerSqueeze`(오프너 → 플랫한 자리) → `allin` 또는 `folded`. 아무도 안 하면
  지금처럼 `flop`.
- 투입액: 폴드는 이미 낸 것 유지(오프너 2.5, 플랫한 자리 2.5 + BB면 앤티), 스퀴즈 콜은 스택.

## 솔버 (`scripts/solve-preflop-3bet.ts`)

플랫한 자리 k, 그 뒤의 자리 m마다 스퀴즈 빈도 `sq[k][m]`, 오프너의 콜 `oSq[k][m]`,
k의 콜 `kSq[k][m]`.

- k의 플랫 가치 = `P(아무도 스퀴즈 안 함) × (플랍 몫 − 낸 것)` +
  `Σ firstSq[m] × [pOpenerCalls × (−낸 것) + (1 − pOpenerCalls) × max(−낸 것, 콜 EV)]`
- 오프너의 가치(k가 플랫했을 때) = `P(없음) × (플랍 몫 − OPEN)` + `Σ firstSq[m] × max(−OPEN, 콜 EV)`
- m의 스퀴즈 가치 = 둘 다 접음 × (OPEN + k가 낸 것 + 남은 죽은 돈) + 오프너 콜 × (승률 × 팟 − 스택)
  + (오프너 폴드, k 콜) × (승률 × 팟 − 스택). 올인 팟 = 두 스택 + 접은 쪽이 낸 것 + 남은 죽은 돈.
- 플랍 몫은 콜러별 표(`CALLERS=1`로 만든 IP·SB 표).

## 성공 기준 (30bb)

1. BTN이 CO 오픈에 플랫 ≤ 20% (콜러별 표만 켰을 때 49%)
2. 플랍 도달률 25~40% (`scripts/flop-reach.ts`, 20bb는 35.9%)
3. 바퀴 사이 3벳·스퀴즈 빈도 변화 < 1%p, 판단당 평균 후회 ≤ 0.02bb

## 순서

1. 엔진 + 가짜 데이터 테스트
2. 솔버 노드 추가, 요약에 스퀴즈 빈도
3. `CALLERS=1` 파이프라인 3바퀴(백그라운드)
4. 기준 확인 → 통과하면 화면(스퀴즈 판 결과)과 30bb 켜기
