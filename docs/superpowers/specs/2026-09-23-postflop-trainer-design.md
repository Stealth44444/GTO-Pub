# 포스트플랍 트레이너 설계

작성 2026-09-23. 이 문서는 조사에서 **실제로 측정한 값**과 그 위에서 내린 판단을 남긴다.
다시 파지 않아도 되게 하는 것이 목적이다.

## 왜 하는가

지금 트레이너는 판단이 하나뿐이다 — 올인이냐 폴드냐. 몇 분이면 바닥이 보이고,
포스트플랍을 못 다루면 "홀덤을 배우는 앱"이라고 하기 어렵다.

목표는 **프리플랍부터 리버까지 한 핸드를 끝까지 치면서 매 판단을 채점받는 것**이다.
액션은 GTO Wizard처럼 크기가 박힌 이산 목록에서 고른다 (`체크 / 벳 28 / 올인 200`).
사용자가 벳 사이즈를 정하지 않는다.

## 결론 요약

| | 상태 |
|---|---|
| 포스트플랍 솔브 | **해결.** 오픈소스 솔버가 이 기계에서 동작 확인 |
| 데이터 크기 | **해결.** 런아웃 단위로 뽑으면 gzip 140KB |
| 프리플랍 솔브 | **미해결.** 쓸 만한 오픈소스가 없음. 직접 만들어야 하고, 경로는 확인됨 |
| 앱 멀티스트릿 | **미착수.** 솔버와 무관하게 필요한 작업이고 양이 적지 않다 |

## 1. 포스트플랍 — 측정값

`b-inary/postflop-solver` (AGPL-3.0, 2023년 개발 중단, ★369).
싱글레이즈 팟, 플랍 `Td9d6h`, 벳 `50%, a` / 레이즈 `2.5x`, 팟 5.5bb.

| 유효 스택 | 솔브 시간 | 메모리 | 전체 트리 저장 |
|---|---|---|---|
| 37.5bb | 32.9초 | 1.97GB | 2,017MB |
| 20bb | 8.4초 | 0.82GB | 839MB |
| 15bb | 8.3초 | 0.85GB | 867MB |
| 10bb | 3.9초 | 0.47GB | 484MB |

수렴은 팟의 0.36~0.45% 착취가능성까지. **솔브 속도는 전혀 병목이 아니다.**

### 병목은 저장 크기였고, 런아웃 단위로 풀린다

839MB는 49×48가지 모든 턴·리버 런아웃의 전략을 담은 값이다. 그런데 한 핸드를
칠 때 소비되는 건 런아웃 하나뿐이고, **보드를 우리가 깔기 때문에 어떤 런아웃을
낼지도 우리가 정한다.**

플랍의 모든 액션 분기 + 고른 턴 카드의 모든 분기 + 고른 리버의 모든 분기만
뽑으면 (20bb 기준):

```
노드 118개 · 0.93MB · gzip 0.14MB     ← 839MB에서 900배 감소
```

gzip 140KB면 지금 `pushfold.json`(32KB)과 같은 급이다. 카테고리 진입 시
지연 로드하면 된다 (`callspots.ts`가 쓰는 방식 그대로).

런아웃을 여러 개 뽑으면 크기는 선형으로만 늘어난다.

### 내보내기 형식

```json
{"line":"", "player":0,
 "actions":["Check","Bet(28)","AllIn(200)"],
 "hands":340,
 "strategy":[0.722, 1.000, ...],   // 핸드 × 액션 빈도
 "ev":[...]}                        // 핸드별 EV
```

`line`이 액션 경로라, 앱은 사용자가 고른 대로 따라가며 조회한다.
액션이 크기가 박힌 목록으로 나오므로 **지금 피드백 패널이 그대로 렌더링한다.**

### 빌드에 필요한 수정 (세 가지)

2023년에 멈춘 저장소라 최신 Rust/의존성에서 그냥은 안 된다. 전부 의존성·컴파일러가
앞서 나가 생긴 문제이고 솔버 로직 결함은 아니다.

1. `Cargo.toml`의 `bincode`를 `=2.0.0-rc.3`으로 고정 — 정식 2.0.1이 끌려오면
   `BorrowDecode` 트레이트 시그니처가 달라 74개 오류
2. `cargo update -p bincode_derive --precise 2.0.0-rc.3` — 매크로만 2.0.1로
   남으면 신 API 코드를 생성해 같은 오류
3. `src/lib.rs` 맨 위에 `#![allow(dangerous_implicit_autorefs)]` — Rust가 이 린트를
   기본 거부로 바꿔서 `action_tree.rs`의 3곳이 걸린다

**앞으로도 Rust가 올라갈 때마다 비슷한 손질이 필요하다.** 개발 중단된 프로젝트에
의존하는 실제 비용이다.

### 라이선스

AGPL-3.0이지만 **우리 용도에는 제약이 없다.** 솔버를 배포하지 않고 오프라인에서
돌려 데이터만 굽기 때문이다. GPL §0:

> The act of running the Program is not restricted, and the output from the Program
> is covered only if its contents constitute a work based on the Program.

GCC로 빌드한 바이너리가 GPL이 아닌 것과 같다. 앱에는 JSON만 들어간다.

단, `bupticybee/TexasSolver`는 저자가 "인터넷으로 서비스를 제공하려면 상용
라이선스를 문의하라"고 별도로 명시했으므로 그쪽은 다르게 봐야 한다.

## 2. 프리플랍 — 여기가 막힌다

### 순환 의존

프리플랍 레인지를 정하려면 "2.5bb로 레이즈하면 그 뒤 포스트플랍에서 얼마를
버는가"를 알아야 한다. 그런데 포스트플랍을 풀려면 양쪽 프리플랍 레인지가 필요하다.

이 순환이 프리플랍 솔브의 본질적 난점이고, **오픈소스에 제대로 푼 물건이 없는
이유**이기도 하다.

### 유일한 후보를 검증했고, 쓸 수 없다

`exinori/DCFR-SOLVER` (MIT, 저작권자 POKERGOSU 2025, 커밋 1개, ★19).
6-max 프리플랍 MCCFR을 제공하고 `preflop → chart-preflop → batch → solve`
파이프라인이 실제로 구현돼 있다 (README에는 없지만 CLI에 있다).

그런데 **포스트플랍을 전혀 호출하지 않는다.** 터미널 값을 이렇게 계산한다:

- 모든 핸드가 베팅 없이 쇼다운까지 간다고 가정 (보드 무작위 샘플 10개 평균)
- 거기에 `--oop-pot-tax` 휴리스틱을 얹음 (기본 0.20: 팟의 20% × 랭크차/5를
  OOP에서 IP로 이전)

즉 순환을 **푼 게 아니라 상수로 우회**했다.

### 대조 실험 (2M 반복, 상수만 변경)

| 스팟 | 세금 0.20 | 세금 0.00 |
|---|---|---|
| UTG RFI | 19.9% | 19.1% |
| HJ RFI | 20.7% | 18.1% |
| CO RFI | 27.5% | **16.8%** |
| BTN RFI | 64.1% | **18.0%** |

**세금을 끄면 BTN이 UTG와 똑같이 18%를 연다. 포지션 차이가 0이다.**

당연하다. 베팅 없이 쇼다운까지 간다면 포지션은 아무 의미가 없다. 포지션의 가치는
전부 포스트플랍에서 나온다.

그리고 켜면 과하게 넘어간다 — BTN 64%는 실제(~45%)보다 한참 넓고, `32s`·`Q2o`·`K2o`까지
연다. 포지션이 도와주는 건 에퀴티를 실현할 수 있는 핸드이지 `Q2o`가 아닌데,
이 휴리스틱은 IP의 모든 핸드를 똑같이 부풀린다.

**결론: 이 솔버가 내는 프리플랍 레인지의 포지션 구조는 전부 손으로 맞춘 상수 하나가
만들어낸 것이다.** 이번 세션의 앤티 문제와 같은 실패 유형이다 — 그럴듯해 보이지만
다른 게임을 푼 결과.

(참고한 "실제 GTO" 수치는 기억에 의존한 값이라 정확하지 않을 수 있다. 다만 세금을
끄면 포지션 구조가 사라진다는 결과는 같은 조건에서 상수만 바꾼 대조라 그 수치와 무관하다.)

### 직접 만드는 경로

포스트플랍 솔버가 손에 있으므로 순환을 실제로 돌릴 수 있다:

```
1. 프리플랍 레인지 초기값 (DCFR-SOLVER 결과를 출발점으로)
2. 각 매치업의 포스트플랍을 푼다           ← postflop-solver
3. 그 EV를 프리플랍 터미널 값으로 쓴다      ← 세금 상수 대신. 여기가 없는 부분
4. 프리플랍 MCCFR 재실행 → 1로
```

2번 배선은 DCFR-SOLVER의 `batch`가 매치업에서 포스트플랍 설정(JSONL)을 뽑아주므로
이미 있다. **없는 건 3번, EV를 되먹이는 부분 하나다.**

비용 추정: 매치업 30개 × 대표 플랍 30개 × 8.4초 ≈ **프리플랍 1회 반복에 2시간**.
몇 번 돌리면 하룻밤. 데스크톱에서 가능한 규모다. (플랍 개수와 수렴에 필요한
반복 횟수는 실측 전 추정치다.)

### DCFR-SOLVER 빌드 수정

`Cargo.toml`의 clap에서 기본 피처를 끈다:

```toml
clap = { version = "4", default-features = false,
         features = ["derive", "std", "help", "usage", "error-context"] }
```

clap의 컬러 출력이 `windows-sys`를 끌어오는데, GNU 툴체인의 `dlltool`이 임포트
라이브러리를 만들지 못한다. rustup 번들 `dlltool.exe`를 PATH에 넣어도 실패한다.
컬러를 끄면 `windows-sys` 의존성 자체가 사라진다.

## 3. 앱 — 솔버와 무관하게 필요한 작업

지금 앱은 판단이 **하나**고 그걸로 끝난다. 한 핸드를 끝까지 치려면 없는 것들:

- **멀티스트릿 상태 기계** — 베팅 라운드, 팟 추적, 액션 히스토리, 스트릿 전환
- **보드 렌더링** — 플랍 3장, 턴, 리버
- **트리 노드 조회** — `line` 경로로 현재 노드의 전략·EV를 찾기
- **액션 집합 확장** — `ActionId`에 `check`, `bet`, `raise` 추가

재사용되는 것도 있다. **피드백 패널은 이미 맞는 모양이다** — 액션별 등급 아이콘·빈도·EV를
한 줄씩 보여주고 고른 줄에 테두리를 친다. 채점도 그대로다: EV 손실 단위가 bb라
`grading.ts`의 경계와 테스트를 건드릴 필요가 없다.

**이 작업은 전략 데이터가 어디서 오든 똑같이 필요하고, 솔버 선택보다 먼저 시작할 수 있다.**

## 4. 정해진 것과 안 정해진 것

**정해진 것**

- 포스트플랍 엔진은 `postflop-solver`. 오프라인 도구로 쓰고 앱에는 JSON만 넣는다
- 데이터는 런아웃 단위로 내보내고 카테고리 진입 시 지연 로드
- 액션은 크기가 박힌 이산 목록. 사용자가 사이즈를 고르지 않는다
- 박아놓은 벳 사이즈가 곧 모델의 제약이다. `콜하는 사람이 최대 1명` 같은 다른
  단순화들과 나란히 README에 적어둔다

- **프리플랍은 핸드의 일부다.** 사용자가 프리플랍에서도 폴드·콜·레이즈를 고르고
  그 선택이 채점된다. 프리플랍을 주어진 상황으로 두고 플랍부터 시작하는 안은
  검토했다가 접었다

**안 정해진 것**

- 첫 프리플랍 상황 (어느 포지션 대 어느 포지션, 스택 깊이)
- 플랍을 몇 개 미리 풀 것인가, 어떤 기준으로 고를 것인가
- 프리플랍 되먹임(2절)을 언제 착수할 것인가 — 그게 서기 전까지 프리플랍 채점의
  근거가 없다는 점이 일정의 핵심 제약이다
- 런아웃을 플랍당 몇 개 뽑을 것인가

**다음에 할 일**

앱의 멀티스트릿 상태 기계부터 시작하는 것이 맞다. 솔버 선택과 무관하게 필요하고,
데이터 형식이 이미 확정됐으므로 막힐 이유가 없다. 프리플랍 되먹임은 그 위에서
판단한다.

## 부록: 재현 방법

```bash
# 포스트플랍
git clone --depth 1 https://github.com/b-inary/postflop-solver.git
cd postflop-solver
# Cargo.toml: bincode를 "=2.0.0-rc.3"으로
cargo update -p bincode_derive --precise 2.0.0-rc.3
# src/lib.rs 맨 위: #![allow(dangerous_implicit_autorefs)]
cargo run --release --example basic     # 저자의 단언문이 전부 통과하는지 확인

# 프리플랍
git clone --depth 1 https://github.com/exinori/DCFR-SOLVER.git
cd DCFR-SOLVER
# Cargo.toml: clap default-features = false (위 참조)
cargo build --release
./target/release/dcfr-solver preflop --iterations 2000000 \
  --chart-output pf.json --matchup-output pf_matchups.json
./target/release/dcfr-solver preflop --iterations 2000000 \
  --oop-pot-tax 0.0 --chart-output pf0.json    # 대조군
```

Windows + GNU 툴체인 기준. `rustup toolchain install stable-x86_64-pc-windows-gnu`.
